# Sources — community orientation

For a question practice answers: how a system behaves, what a vendor recommends, what practitioners have run into.

- **Authoritative for a claim**: the source that owns the behavior — official documentation, a specification, a changelog or release note, the code or its issue tracker. Forums, Q&A sites, and posts report experience; they ground a claim about what people observed, and point to the owning source for a claim about how the system works.
- **Version and recency**: behavior changes between releases. Note the version or date a source speaks to, and whether it still holds for the version in question.
- **Applicability**: a recommendation holds under its own conditions — scale, configuration, environment. Carry those conditions with the claim, and say where the person's case may differ.
- **Agreement**: several posts repeating one source are one source; trace them to it.
