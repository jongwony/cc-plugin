# Dark or locked Mac

Binds before an act that reads or drives a window on this Mac's screen — an ocu call (an ocu-agent MCP tool, or `ocu js` run directly or by a script), a raw Accessibility read, an app plugin's AX helper — before delegating to an agent that makes such acts without a shell (`ocu-agent:ocu-operator`), and when such an act fails or returns a window without its content.

- **A locked Mac does not end GUI work.** ocu's Locked Use opens the locked session for the run wherever `ocu locked-use status --json` reports `available` true, and it needs the display on.
- **The lock and the display are two states.** `caffeinate -u` turns the display on; the lock opens through an ocu call under Locked Use, so read the lock again after that call and before an act through another reader. Read it from `ocu locked-use status --json` (`session.state`), or from `CGSSessionScreenIsLocked` in `ioreg -n Root -d1`, a key present only while locked; `IOConsoleLocked` reads `No` on a locked Mac.
- **Before the act, read `ocu locked-use status --json`** (`session.state`, `available`).
  - Locked, `available` true → start `caffeinate -u -t <seconds>` detached, sized to the run and 120 at least, unless `pgrep -f 'caffeinate -u'` finds one (only a `-u` caffeinate keeps the display on); wait 2 s; then make the ocu call or the delegation. An act through any other reader follows one ocu call that has opened the session.
  - Locked, `available` false → make no such act; report the cause. Enabling Locked Use (`ocu locked-use enable`) is the user's act.
- **The lock closes window content to Accessibility readers other than Locked Use.** A process calling `AXUIElement` directly gets each window back as the application element with only the menu bar beneath it, and a helper built on that can return stale rows. Once an ocu call has opened the session, raw AX and the helpers read normally.
- **Chrome through the Claude in Chrome extension works on a locked or dark Mac with no wake** — tabs, page text, navigation, scripts, form input and its own screenshots.
- **"Locked Use could not observe a protected GUI session becoming unlocked"** means Locked Use did not see the session open. A dark display causes it, and so does a call made in the second the display comes on: wake it again as above and retry once. The same failure on the retry is the finding. Report it with the lock state, the last `Display is turned` line of `pmset -g log`, the power source and the lid state: it has also occurred with the display reported on, and on battery with the lid closed `caffeinate -u` did not light the display.
- **Locked Use opens the session for the run and leaves it open after the run.** The Mac's own auto-lock closes it again. Add no relock step.
